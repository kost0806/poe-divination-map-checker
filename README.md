# poe-divination-map-checker

Path of Exile 아틀라스 맵별 **디비네이션 카드 기대수익** 계산기.

현재 리그(커런시 익스체인지) 시세와 게임 데이터를 결합해, 맵마다 어떤 카드가
얼마나 나오고 그게 얼마어치인지 추정한다.

## 데이터 출처

| 항목 | 출처 | 갱신 주기 |
|---|---|---|
| 맵별 드랍 카드 풀 / 카드 DropLevel | PoEDB (게임 클라이언트 데이터) | 패치 단위 |
| 카드 골드 수수료 (`CurrencyExchange.GoldPurchaseFee`) | PoEDB | 패치 단위 |
| 맵 티어 / 지역 레벨 / 몹 밀도 / 클리어 지표 | PoEDB | 패치 단위 |
| 카드 시세 · 24h 거래량 | 인게임 커런시 익스체인지 (PoEDB 미러) | 상시 |
| 현재 리그 | pathofexile.com 공식 API | 상시 |

패치 단위 데이터는 `npm run data:build` 로 크롤해 `data/static.json` 에 커밋해 두고,
시세만 런타임에 갱신한다. 시세 조회가 실패하면 `data/prices.json` 스냅샷으로 폴백한다.

## 기대수익 모델

GGG는 카드별 드랍 확률을 공개하지 않는다. 게임 데이터(dat) 1535개 테이블에도
카드 단위 가중치는 없고, 거래량으로 역산하는 것도 불가능하다 —
`거래량 = 드랍률 × Σ(그 카드가 나오는 맵들의 실행 횟수)` 라서 맵 인기도와 드랍률이
분리되지 않는다(미지수가 방정식보다 많아 식별 불가).

대신 **커런시 익스체인지 골드 수수료**를 희소성 신호로 쓴다. GGG가 아이템마다 직접
매긴 정적 값이라 시장 시세·맵 인기도와 무관하다. 한 맵에서만 드랍되는 카드 90종
(38개 맵)으로 검증하면 — 같은 맵 안에서는 실행 횟수가 약분되므로 거래량 비율이
상대 드랍률의 불편추정치가 된다 — `log(거래량) ~ log(골드)` 기울기가 **−1.005**로,
드랍률이 골드 수수료에 거의 정확히 반비례한다.

카드 c의 절대 드랍률을 `A · gold_c^(-γ)` 로 둔다. `A`는 모든 맵에 똑같이 곱해지는
전역 상수라 **맵 간 순위에는 영향이 없고** 절대 수익 환산에만 쓰인다.

```
pool(m) = { 맵 m 전용 카드 c : c.dropLevel ≤ 맵 m 지역레벨 }

S_m = Σ gold_c^(-γ)                 맵 m의 상대 카드 드랍량
E_m = Σ gold_c^(-γ) × 시세_c         맵 m의 상대 기대수익   ← 맵 간 순위 기준

A          = 맵당 카드수 가정 ÷ 전체 맵 평균 S
1회당 수익  = A × E_m × (몹밀도_m / 평균)
시간당 수익 = 1회당 수익 × 60 / (기준시간 × 평균클리어 / 클리어_m)
```

맵 전용 카드는 113개 맵 중 107개가 정확히 4장이라 풀 크기 정규화 문제가 없다.
지역 제한 없이 아무 데서나 나오는 전역 풀 카드는 모든 맵에 똑같이 얹히는 값이라
비교에서 제외했다.

`A`의 근거가 되는 "맵 1회당 카드 드랍 수"는 공개 데이터가 없다. 따라서
**맵 간 순위와 배율은 유효하지만 절대 카오스 값은 가정에 의존한다.**

24h 거래량을 드랍률로 직접 쓰지 않는 이유는 유동성 편향이 크기 때문이다. 예를 들어
Burial Chambers 전용 카드 거래량의 89.7%가 The Doctor인데, 나머지 카드가 0카오스라
아무도 거래하지 않아서 생기는 착시다. 거래량은 검증용 참고 지표로만 표시한다.

## 개발

```bash
npm install
npm run data:build     # 패치 단위 구조 데이터 크롤 (~20초, 수백 요청)
npm run data:prices    # 시세 스냅샷 갱신
npm run dev
```
